## Deviations
- `total_checkins` is also reported as 0 when fewer than 3 riders were active (the prompt only said `active_riders`), because the count would otherwise reveal one or two riders' activity.
- A previous period with fewer than 3 distinct riders counts as no data (+100%), so the percent change cannot expose a small previous bucket. A previous period with no check-ins also reports +100.0. Both are written into the endpoint description.
- `sql/analytics_boston.sql` takes distinct riders from `rider_events` (the hourly `unique_users` cannot be summed across hours) and gates the `stop_popularity_hourly` counts with it. It names `stop_popularity_hourly`, which is not yet in migrations 0001-0004 (promised in v0.1, issue #22).
- New Protocol method `rider_events_all(since)` returns all riders' events for aggregate use; its docstring says callers must reduce to counts and never return ids.
- Day buckets use UTC dates.
- The week/month windows are rolling (`now - 7 days` / `now - 30 days`), as in 006.
