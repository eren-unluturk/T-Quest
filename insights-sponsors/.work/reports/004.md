## Response validation approach
Compared response shape with the OpenAPI schema using a small recursive helper (`tests/openapi_shape.py`): it follows `$ref`, arrays and objects, and asserts key sets equal the schema properties, required keys are present, and nulls only appear on nullable fields. I chose this over `jsonschema` because jsonschema does not understand OpenAPI 3.0 `nullable`.

## Deviations
- `/fun-facts` `random=true` uses `random.sample` of up to `limit` facts; `random=false` returns the first `limit` in seed order.
- Local picks: `stores_near_stop` is asked for all stores, then stores with no active `local_pick` offers are dropped, then the limit applies, so a stop can return fewer than `limit` only when fewer stores qualify.
- The query param is declared as `random_order` with alias `random` (avoids shadowing the module).
- `tests/test_memory_repo.py` keeps its own `repo` fixture (same behavior as the new conftest one).
