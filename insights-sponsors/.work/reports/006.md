## Deviations
- Added Protocol methods beyond the two the prompt named: `stops()`, `stores()`, `route_stops()`, `stop_popularity(since)`, alongside `rider_events` and `place_visits`. Recommendations need them. `stop_popularity` returns an aggregate only, mirroring the aggregate view.
- Seed events store `days_ago` and `hour` and the memory repo converts them at load, so the demo data never goes stale. Days avoid the 7/28/30 day edges so tests are not flaky.
- Seed lines are simplified ids (Red, Orange, Green, Blue), not Green-B and so on.
- Score definitions (all in 0-1): neighborhood 1 / popularity rank among eligible, route 0.8 * shared stops / max shared, place affinity 0.6 * category share. Ranking across kinds is by score, then id.
- Period windows are rolling (week = 7 days, month = 30 days), and weeks start on Monday to match `time_bucket('1 week')`.
- `stops_visited` is the number of check-ins in the period; `unique_stops` is distinct stops.
- `analytics_me.sql` holds several named queries (`-- name: ...`) in one file.
