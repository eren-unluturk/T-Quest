## Deviations
- Fixtures were captured from the public API without a key (small page-limited samples).
- Stops for `route_stops`: rail routes use `filter[location_type]=1` (parent stations), bus routes use `location_type=0`; one request per route and direction, `stop_sequence` = position in the response (assumes the API returns stops in route order for a route+direction filter).
- `load_static` never overwrites the curated `is_freedom_trail` and `neighborhood` columns.
- Alert `active_end` is NULL when any active period is open-ended, otherwise the latest end; `active_start` is the earliest start.
- `ingest` keeps predictions to routes whose `mode` is subway or light_rail in the `routes` table (run load_static first; with an empty routes table predictions are skipped).
- Client does not read `Retry-After`; it uses exponential backoff (1s, 2s, 4s, 8s).
- Alerts that disappear from the feed are not closed or deleted; `active_alerts` relies on `active_end`.
