## Deviations
- Fixed a bug in my own 001 runner: `-- migrate:no-transaction` files were sent as one multi-statement string, which Postgres runs inside an implicit transaction, so CREATE MATERIALIZED VIEW ... continuous would have failed. The runner now splits no-transaction files into individual statements (dollar-quote, quote and comment aware) and runs each in autocommit.
- Consequence: a no-transaction migration that fails midway is not rolled back and is not recorded; re-running relies on every statement being idempotent (they are written that way).
- `home_line` cutoff uses `time_bucket('7 days', now() - 28 days)` so whole weekly buckets are counted ("last 4 weeks" is bucket-aligned, not exact 28 days).
- `friends` scope follows directed rows `friends(user_id = p_user)`; game-engine must insert both directions for a mutual friendship (also in SCHEMA.md).
- `users_affected_by_alert` is created through a DO block guarded by `to_regclass('public.alert_entities')`; 0003 exists, so it is created.
- `leaderboard()` returns only users with ledger rows in the window and scope (no zero-point rows).
- Tests use a unique route id per run and filter to their own users, because the append-only ledger keeps rows from earlier runs.
- Risk to check on the first live run: FILTER clauses inside continuous aggregates need TimescaleDB 2.7+ (the compose image is latest).
